# CXIM 办公系统集成指南

> 本文面向办公系统的后端与前端开发人员，说明如何把 CXIM 聊天能力接入现有办公系统：
> 用户/群组数据由办公系统维护并同步到 CXIM，页面右下角显示聊天图标，点击展开聊天面板；
> 同时 CXIM 仍可独立部署使用（自带登录、注册与群组管理），两种模式共用一套代码。

---

## 1. 两种使用模式

| 模式 | 适用场景 | 登录方式 | 用户/群组来源 |
| --- | --- | --- | --- |
| 独立使用 | 单独部署的聊天工具 | CXIM 自带登录页 / 注册页 | 自行注册；管理员 admin 建群、改名、移人 |
| 集成使用 | 作为办公系统的一个模块 | 办公系统通过 SSO 单点登录 | 办公系统通过数据接口同步 |

两种模式可以同时启用：集成时办公系统同步的账号与独立注册的账号都存在同一套用户表中。

## 2. 部署与配置

CXIM 根地址以下称为 `https://chat.example.com`（本地演示为 `http://localhost:5300`）。

`server/appsettings.json`：

```json
{
  "Database": {
    "Provider": "Sqlite",
    "Sqlite": "Data Source=layim.db",
    "SqlServer": "Server=localhost;Database=LayimChat;User Id=sa;Password=***;TrustServerCertificate=True;Encrypt=False",
    "MySql": "Server=localhost;Port=3306;Database=layimchat;User=root;Password=***;CharSet=utf8mb4",
    "PostgreSql": "Host=localhost;Port=5432;Database=layimchat;Username=postgres;Password=***"
  },
  "Integration": {
    "ApiKey": "办公系统调用接口的密钥，请务必修改",
    "SsoSecret": "SSO 签名密钥，请务必修改，与办公系统保持一致"
  },
  "Cookie": {
    "SameSite": "Lax"
  }
}
```

- `Database:Provider`：`Sqlite` / `SqlServer` / `MySql` / `PostgreSql`，也可用环境变量 `Database__Provider` 覆盖。
- `Integration:ApiKey`：数据接口的请求头 `X-Api-Key`。
- `Integration:SsoSecret`：SSO ticket 的 HMAC 密钥。
- `Cookie:SameSite`：
  - `Lax`（默认）：CXIM 独立访问，或与办公系统同主域（如 `office.example.com` 与 `chat.example.com` 同属 `example.com`）；
  - `None`：办公系统与 CXIM **跨站点** iframe 内嵌时必须设置，且必须启用 HTTPS（浏览器要求 `SameSite=None` 必须 `Secure`）。

> 跨域 iframe 内嵌时，服务器还需要允许被 `https://office.example.com` 嵌入，
> 可通过反向代理（Nginx）添加 `X-Frame-Options: ALLOW-FROM` 或 `Content-Security-Policy: frame-ancestors https://office.example.com`。

## 3. 数据接口（办公系统 → CXIM）

所有接口：

- 前缀：`/api/integration`
- 请求头：`X-Api-Key: <Integration:ApiKey>`
- 请求体：`Content-Type: application/json; charset=utf-8`
- 返回：统一 `{ "code": 0, "msg": "", "data": ... }`，`code=0` 成功，非 0 失败且 `msg` 为原因。

### 3.1 用户列表

`GET /api/integration/users`

返回示例：

```json
{
  "code": 0, "msg": "",
  "data": [
    { "id": "100001", "username": "张三", "sign": "研发部", "avatar": "/dist/layim-assets/images/default.png", "status": "online" }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| id | CXIM 内部用户ID（数字字符串），办公系统建议持久保存映射关系 |
| username | 登录名，全系统唯一，2–20 个字符 |
| sign | 个性签名 / 职位等展示文字 |
| avatar | 头像地址；为空时接口已回落为默认头像 |
| status | 在线状态（online / offline，仅供参考） |

### 3.2 新增或更新用户

`POST /api/integration/users`

请求体：

```json
{
  "username": "张三",
  "password": "初始密码（可省略，省略时新建用户默认 123456）",
  "sign": "研发部 · 工程师",
  "avatar": "https://office.example.com/avatar/zhangsan.png",
  "groups": ["D001", "D002"]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| username | 是 | 用户的唯一标识；办公系统通常用工号或账号 |
| password | 否 | 新建时作为初始密码；更新时传了才会改密码 |
| sign | 否 | 个性签名 |
| avatar | 否 | 头像 URL（外链需办公系统可公网/内网访问） |
| groups | 否 | 所属部门（群组）ID 列表；**传入即精确覆盖**，`[]` 表示不属于任何群；**不传**表示新建时加入全部群、已存在用户群关系不变 |

返回：

```json
{ "code": 0, "msg": "", "data": { "id": "100010", "username": "张三", "created": true } }
```

错误示例：`{"code":1,"msg":"群组不存在：D009，请先创建群组"}`

> 建议集成顺序：先同步群组（3.4），再同步用户（3.2），否则群组 ID 校验会失败。

### 3.3 删除用户

`DELETE /api/integration/users/{user}`

`{user}` 可以是用户名或用户ID（中文需 URL 编码）。

连带清理：好友关系、群成员关系、该用户发出的单聊/群聊消息。返回 `{"code":0,"msg":""}`。

### 3.4 群组列表

`GET /api/integration/groups`

```json
{
  "code": 0, "msg": "",
  "data": [
    { "id": "D001", "name": "研发部", "ownerId": "", "members": [{ "id": "100001", "username": "张三" }] }
  ]
}
```

### 3.5 新增或更新群组（部门）

`POST /api/integration/groups`

```json
{ "id": "D001", "name": "研发部" }
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| id | 否 | 建议直接用办公系统的部门ID（≤50 字符，稳定不变）；省略时自动生成数字ID |
| name | 是 | 群名称，1–30 个字符 |

返回：`{ "code": 0, "msg": "", "data": { "id": "D001", "name": "研发部", "created": true } }`

已存在的群组只更新名称，并实时向在线成员推送 `GroupRenamed`，界面上的群列表与聊天窗口标题立即刷新。

### 3.6 删除群组

`DELETE /api/integration/groups/{id}`

连带删除成员关系与该群聊天记录，并实时通知在线成员移除界面上的群。

### 3.7 添加群成员

`POST /api/integration/groups/{id}/members`

```json
{ "user": "张三" }
```

`user` 可传用户名或用户ID。重复调用幂等：返回 `added=false`。返回 `{"code":0,"msg":"","data":{"groupId":"D001","userId":"100010","added":true}}`

### 3.8 移除群成员

`DELETE /api/integration/groups/{id}/members/{user}`

`{user}` 可传用户名或用户ID（中文需 URL 编码）。被移出的在线用户会立即收到 `RemovedFromGroup` 并从界面移除该群。

> 3.7 / 3.8 是单个成员维度的增量接口；3.2 的 `groups` 字段是整组用户的批量对账方式，二者可混用。

### 3.9 调用示例（curl）

```bash
# 建群
curl -X POST https://chat.example.com/api/integration/groups \
  -H "X-Api-Key: <ApiKey>" -H "Content-Type: application/json" \
  -d '{"id":"D001","name":"研发部"}'

# 同步用户并设置部门
curl -X POST https://chat.example.com/api/integration/users \
  -H "X-Api-Key: <ApiKey>" -H "Content-Type: application/json" \
  -d '{"username":"张三","password":"Init@123","sign":"研发部","groups":["D001"]}'
```

## 4. 单点登录（SSO）

办公系统已登录用户点击聊天图标时，不需要再输入 CXIM 账号密码，而是由办公系统签发票据，跳转到 CXIM 自动登录。

### 4.1 票据格式

```
ticket = Base64Url( username + "|" + unixSeconds + "|" + hmacHex )
hmacHex = HMAC-SHA256(SsoSecret, username + "|" + unixSeconds) 的小写十六进制
```

- 有效期 5 分钟（以服务器时间为准，注意时钟同步）；
- 用户不存在时 CXIM 自动开户（默认加入所有群，便于演示；如需严格按部门，请先用 3.2 同步）。

### 4.2 跳转地址

```
GET https://chat.example.com/api/auth/sso?ticket=<ticket>
```

校验通过后写入登录 Cookie 并 302 跳转到聊天首页（带 `embed=1` 时跳转到内嵌版）。

### 4.3 办公系统后端的换取接口（推荐做法）

办公系统后端提供一个「取 SSO 地址」的接口给前端调用（不要把 SsoSecret 暴露到浏览器）：

```
GET /api/chat/sso-url        ← 办公系统自身的接口，需校验当前登录用户
返回：{ "url": "https://chat.example.com/api/auth/sso?ticket=..." }
```

伪代码（任意语言通用）：

```
unix  = now()
raw   = username + "|" + unix
sig   = hmac_sha256_hex(SsoSecret, raw)
ticket = base64url(raw + "|" + sig)
return "https://chat.example.com/api/auth/sso?ticket=" + ticket
```

> 注意 base64 需为 **URL 安全**变体（`+`→`-`、`/`→`_`，去掉 `=`），否则 ticket 里的特殊字符会破坏 URL。

## 5. 页面集成：右下角图标 + 聊天面板

### 5.1 只需要加一段 script

在办公系统框架页（母版页 / layout）的 `</body>` 前加入：

```html
<script src="https://chat.example.com/embed.js"
        data-base="https://chat.example.com"
        data-ticket-url="/api/chat/sso-url"
        data-width="380"
        data-height="600"
        data-title="在线聊天"></script>
```

| 属性 | 必填 | 说明 |
| --- | --- | --- |
| src | 是 | 挂件脚本地址，指向 CXIM 的 `embed.js` |
| data-base | 否 | CXIM 根地址；省略时按脚本自身地址推断 |
| data-ticket-url | 否 | 办公系统自己的「取 SSO 地址」接口，返回 `{ "url": "..." }` 或纯文本 URL；不配置则直接打开 CXIM（会显示登录页） |
| data-width | 否 | 面板宽度，默认 380；窄屏（≤768px）自动铺满 |
| data-height | 否 | 面板高度，默认 600；自动收缩到视口内 |
| data-open | 否 | `true` 时页面加载后自动展开 |
| data-badge | 否 | 未读消息红点，默认 `true` |

挂件会：

1. 在页面右下角渲染一个 56px 圆形图标（`z-index` 很高，不遮挡业务内容）；
2. 首次点击时才创建 iframe（懒加载，不影响办公系统首屏性能）；
3. 点击图标展开 / 收起面板；面板内是 CXIM 的 `index.html?embed=1`（铺满面板）；
4. 未展开时收到新消息，会在图标右上角显示未读数（99+ 封顶）；
5. 用户退出登录后自动收起面板并销毁 iframe。

### 5.2 也可用 JS API 控制

```html
<script src="https://chat.example.com/embed.js" data-base="https://chat.example.com"></script>
<script>
  CXIM.open();     // 展开面板
  CXIM.close();    // 收起面板
  CXIM.toggle();   // 切换
</script>
```

### 5.3 宿主页面可监听的事件（postMessage）

聊天面板通过 `window.postMessage` 向宿主页面发送事件，`e.data.source === 'cxim'`：

| type | 触发时机 | 附带字段 |
| --- | --- | --- |
| `cxim:ready` | 聊天面板登录完成、主面板就绪 | `username` |
| `cxim:message` | 收到新消息 | `username`、`content`、`id`、`chatType` |
| `cxim:logout` | 用户在面板内退出登录（面板会自动销毁） | 无 |

```javascript
window.addEventListener('message', function (e) {
  if (!e.data || e.data.source !== 'cxim') return;
  if (e.data.type === 'cxim:message') {
    // 例如播放提示音、更新办公系统的未读角标
    console.log('新消息', e.data.username, e.data.content);
  }
});
```

### 5.4 iframe 权限

挂件创建的 iframe 已声明 `allow="microphone; camera; clipboard-write"`，语音消息、视频通话、截图粘贴在集成环境下可正常使用（视频通话需 HTTPS）。

## 6. 内嵌模式说明

`index.html?embed=1` 时页面进入内嵌模式：

- 取消主面板的 260px 固定宽度与右下角定位，改为铺满 iframe；
- 聊天窗口全屏覆盖 iframe，隐藏左侧多会话切换栏（通过主面板列表切换会话）；
- 关闭聊天窗口即回到主面板（不会跳出 iframe）；
- 通过 5.3 的 postMessage 事件与宿主页面通信。

独立访问 `index.html`（不带 `embed=1`）时布局与原有桌面/移动端表现完全一致。

## 7. 推荐集成流程

1. 部署 CXIM，修改 `Integration:ApiKey`、`Integration:SsoSecret`（与办公系统约定一致）。
2. 办公系统后台配置定时/事件触发的数据同步：
   - 部门变化 → `POST /api/integration/groups`（建或改名）、`DELETE /api/integration/groups/{id}`（撤部门）；
   - 员工入职/调岗 → `POST /api/integration/users`（`groups` 传最新部门列表）；
   - 员工离职 → `DELETE /api/integration/users/{user}`。
3. 办公系统后端实现 `GET /api/chat/sso-url`。
4. 办公系统框架页引入 `embed.js`（第 5.1 节）。
5. 验证：登录办公系统 → 右下角出现图标 → 点击展开 → 免登录进入聊天 → 右侧面板显示同步的部门与同事。

## 8. 常见问题

**Q1：面板里显示「CXIM 登录」而不是已登录状态？**
- `data-ticket-url` 未配置或返回为空；
- ticket 过期（>5 分钟）或 `SsoSecret` 两边不一致；
- 办公系统与 CXIM 跨站点时，Cookie 需要 `SameSite=None` + HTTPS（见第 2 节）。

**Q2：iframe 里空白或被拒绝加载？**
- 服务器未允许被办公系统域名嵌入（X-Frame-Options / CSP frame-ancestors）；
- 混合内容：HTTPS 页面里嵌了 HTTP 的 CXIM。

**Q3：同步用户时报「群组不存在」？**
- 先同步群组再同步用户；或检查 `groups` 中的部门ID是否与 `GET /api/integration/groups` 返回的 `id` 一致。

**Q4：同步后成员收不到群消息？**
- 该用户正多端在线时，服务端会同步其所有在线连接加入/移出 SignalR 组，无需重连；若仍异常，确认用户确实在成员列表中（`GET /api/integration/groups`）。

**Q5：头像不显示？**
- `avatar` 传空字符串时会回落默认头像；外链头像需允许跨域访问，建议由办公系统提供可直接访问的图片地址。

**Q6：管理员改了群名，办公系统那边要不要同步？**
- CXIM 内的改名只影响 CXIM；若办公系统为权威数据源，下次同步群组时以办公系统的名称为准（`POST /api/integration/groups` 会覆盖名称）。

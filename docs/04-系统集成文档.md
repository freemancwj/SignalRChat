# CXIM 系统集成文档

> 面向第三方系统（如公司管理系统、OA、ERP）的接入指南。
> 聊天系统提供两种集成能力：**单点登录（SSO）** 和 **服务端 API（ApiKey）**。

---

## 1. 集成能力总览

| 能力 | 用途 | 认证方式 |
|---|---|---|
| 单点登录 SSO | 业务系统用户点击"进入聊天"免登录直达聊天页面 | HMAC-SHA256 签名 ticket |
| 用户同步 | 业务系统新增/修改账号时同步聊天账号 | 请求头 `X-Api-Key` |
| 用户列表 | 获取聊天系统全部用户用于账号对照 | 请求头 `X-Api-Key` |
| 消息推送 | 业务系统向用户/群推送系统通知（审批提醒等） | 请求头 `X-Api-Key` |

**配置项**（`server/appsettings.json`，生产环境务必修改默认值）：

```json
"Integration": {
  "ApiKey": "cxim-dev-api-key-change-me",
  "SsoSecret": "cxim-dev-sso-secret-change-me"
}
```

也可用环境变量覆盖：`Integration__ApiKey`、`Integration__SsoSecret`。

## 2. 单点登录（SSO）

### 2.1 流程

```
用户在业务系统点击"进入聊天"
   │
   ▼
业务系统后端生成 ticket（含用户名、时间戳、HMAC 签名）
   │
   ▼
浏览器跳转  https://<聊天系统>/api/auth/sso?ticket=<ticket>
   │
   ▼
聊天系统校验签名 → 建立登录 Cookie → 302 跳转 /index.html
```

- ticket 有效期 **5 分钟**，过期需从业务系统重新点击。
- 用户在聊天系统不存在时**自动开户**（随机密码、自动互加好友、加入所有群）。
- 校验失败时显示"单点登录失败"错误页（不泄露具体原因以外的信息）。

### 2.2 ticket 生成算法

```
message  = "{用户名}|{unix秒级时间戳}"
sign     = HMACSHA256(key=SsoSecret, message).hex().toLower()   // 64位小写十六进制
payload  = "{用户名}|{unix秒级时间戳}|{sign}"
ticket   = UrlSafeBase64( UTF8(payload) )                        // + → -, / → _, 去掉 =
```

最终跳转地址（ticket 建议再做一次 URL Encode 保险）：

```
https://<聊天系统>/api/auth/sso?ticket={ticket}
```

> 服务端同时兼容标准 Base64 和 URL 安全 Base64，但标准 Base64 含 `+ / =`，放 URL 必须编码，推荐直接用 URL 安全 Base64。

### 2.3 各语言生成示例

**C#（ASP.NET / .NET 业务系统）**

```csharp
string GenerateSsoUrl(string chatBaseUrl, string ssoSecret, string username)
{
    var ts = DateTimeOffset.UtcNow.ToUnixTimeSeconds();
    using var hmac = new System.Security.Cryptography.HMACSHA256(
        System.Text.Encoding.UTF8.GetBytes(ssoSecret));
    var sign = Convert.ToHexString(
        hmac.ComputeHash(System.Text.Encoding.UTF8.GetBytes($"{username}|{ts}")))
        .ToLowerInvariant();
    var payload = System.Text.Encoding.UTF8.GetBytes($"{username}|{ts}|{sign}");
    var ticket = Convert.ToBase64String(payload)
        .Replace('+', '-').Replace('/', '_').TrimEnd('=');
    return $"{chatBaseUrl}/api/auth/sso?ticket={ticket}";
}
```

**Java（Spring 业务系统）**

```java
String generateSsoUrl(String chatBaseUrl, String ssoSecret, String username) throws Exception {
    long ts = System.currentTimeMillis() / 1000;
    Mac mac = Mac.getInstance("HmacSHA256");
    mac.init(new SecretKeySpec(ssoSecret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
    byte[] raw = mac.doFinal((username + "|" + ts).getBytes(StandardCharsets.UTF_8));
    StringBuilder sign = new StringBuilder();
    for (byte b : raw) sign.append(String.format("%02x", b));
    String payload = username + "|" + ts + "|" + sign;
    String ticket = Base64.getUrlEncoder().withoutPadding()
        .encodeToString(payload.getBytes(StandardCharsets.UTF_8));
    return chatBaseUrl + "/api/auth/sso?ticket=" + ticket;
}
```

**Node.js**

```javascript
const crypto = require('crypto');
function generateSsoUrl(chatBaseUrl, ssoSecret, username) {
  const ts = Math.floor(Date.now() / 1000);
  const sign = crypto.createHmac('sha256', ssoSecret)
    .update(`${username}|${ts}`).digest('hex');
  const ticket = Buffer.from(`${username}|${ts}|${sign}`, 'utf8')
    .toString('base64url'); // Node 15+，URL 安全且无 padding
  return `${chatBaseUrl}/api/auth/sso?ticket=${ticket}`;
}
```

**业务系统前端**：把后端生成的地址作为链接/按钮目标即可：

```html
<a href="https://chat.example.com/api/auth/sso?ticket=ey..." target="_blank">进入聊天</a>
```

> 注意：ticket 必须由**后端**生成（SsoSecret 不能出现在前端代码里），且生成后 5 分钟内有效，建议"点击时实时生成"而不是页面加载时生成。

## 3. 服务端集成 API

统一约定：

- Base URL：`http(s)://<聊天系统>`
- 认证头：`X-Api-Key: <Integration:ApiKey>`，缺失或错误返回 **HTTP 401**
- 请求/响应均为 JSON（UTF-8），响应统一格式 `{ code, msg, data }`，`code=0` 成功

### 3.1 用户列表

```
GET /api/integration/users
```

响应：

```json
{
  "code": 0, "msg": "",
  "data": [
    { "id": "100001", "username": "测试1", "sign": "测试内容1", "avatar": "", "status": "online" }
  ]
}
```

### 3.2 同步用户（创建或更新）

```
POST /api/integration/users
Content-Type: application/json

{ "username": "张三", "password": "123456", "sign": "技术部", "avatar": "https://.../a.png" }
```

| 字段 | 必填 | 说明 |
|---|---|---|
| username | 是 | 2-20 字符，存在即更新、不存在即创建 |
| password | 否 | 创建时缺省为 `123456`；更新时提供才修改 |
| sign / avatar | 否 | 仅在创建后更新场景生效（创建时取默认值） |

行为：

- **创建**：自动与其他所有用户互加好友、加入所有群组（与注册行为一致），返回 `created=true`
- **更新**：按提供的字段更新签名/头像/密码

响应：`{ "code": 0, "data": { "id": "100006", "username": "张三", "created": true } }`

### 3.3 发送消息（系统通知推送）

```
POST /api/integration/messages
Content-Type: application/json

{
  "fromUser": "系统通知",
  "toType": "friend",
  "toUser": "测试1",
  "content": "您的请假单已审批通过"
}
```

| 字段 | 说明 |
|---|---|
| fromUser | 发送者，支持**用户ID或用户名**（建议先通过 3.2 建一个"系统通知"账号） |
| toType | `friend`（单聊）或 `group`（群聊） |
| toUser | friend 时：接收者ID或用户名；group 时：群ID（字符串，如 `"101"`，可通过网页端 init 数据或数据库 ChatGroups 表获取） |
| content | 消息内容，支持 LayIM 语法（`img[url]`、`file(url)[文件名]`、`face[表情]`） |

效果：消息**落库**（对方下次上线可查到历史记录），且对方**在线时实时推送**到聊天窗口（走 SignalR，与网页端发消息完全一致）。

响应：`{ "code": 0, "data": { "id": 20 } }`

**curl 示例**

```bash
curl -X POST http://localhost:5300/api/integration/messages \
  -H "X-Api-Key: cxim-dev-api-key-change-me" \
  -H "Content-Type: application/json" \
  -d "{\"fromUser\":\"系统通知\",\"toType\":\"friend\",\"toUser\":\"测试1\",\"content\":\"您有新的待办事项\"}"
```

### 3.4 错误响应

| 场景 | 返回 |
|---|---|
| ApiKey 缺失/错误 | HTTP 401 `{ "code": 401, "msg": "ApiKey 无效或缺失..." }` |
| 参数校验失败 | HTTP 200 `{ "code": 1, "msg": "具体原因" }`（聊天系统业务约定） |

## 4. 典型集成方案（公司管理系统）

1. **账号同步**：管理系统的用户增删改事件中调用 `POST /api/integration/users`，保持两边账号一致（用户名建议用工号/登录名）。
2. **免密入口**：管理系统菜单加"在线聊天"，点击时后端实时生成 SSO 地址并跳转。
3. **消息通知**：审批流转、任务分派等事件调用 `POST /api/integration/messages`，由"系统通知"账号推送给相关员工；也可推送到指定群组（如"技术部"群）。

---

## 5. 安全建议

- 生产环境务必修改 `Integration:ApiKey` 和 `Integration:SsoSecret` 为足够长的随机串，并通过环境变量或密钥管理服务注入，不要提交到代码库。
- ApiKey 接口仅供**服务端之间**调用，不要把 ApiKey 下发到浏览器/App 端。
- 聊天系统建议部署在**内网或 HTTPS** 之后；SSO ticket 虽有时效和签名，明文 HTTP 仍有被重放的风险窗口。
- SSO 用户名即聊天账号，业务系统需保证用户名唯一且稳定。
